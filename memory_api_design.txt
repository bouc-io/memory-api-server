#### Memory Retrieval Strategy

When processing a new message in an assignment:

1. **Check assignment settings** for memory configuration
2. **Extract context** from the current message and recent conversation
3. **Retrieve memories** using this priority system:

**Priority 1: Critical Importance**
- Always include ALL active `critical` memories (persona, core instructions)
- These define fundamental behavior and must always be present

**Priority 2: High Relevance + High Importance**
- Semantic search with `min_relevance: 0.8`
- Filter by `importance: high`
- Include top 2-3 results

**Priority 3: Fill Remaining Slots**
- Continue semantic search for medium/low importance
- Fill up to `max_memories` limit (e.g., 5 total)

#### Authentication
All endpoints require a JWT Bearer token in the `Authorization` header.
The `user_id` is derived from the `preferred_username` claim in the token.

**Example retrieval logic:**
```python
def retrieve_memories(context, user_id, max_memories=5):
    # Step 1: Get all critical memories
    critical = db.query(
        user_id=user_id,
        importance='critical',
        is_active=True
    )
    
    results = list(critical)
    remaining_slots = max_memories - len(results)
    
    if remaining_slots > 0:
        # Step 2: Semantic search for high importance
        context_embedding = generate_embedding(context)
        high_relevant = vector_db.search(
            embedding=context_embedding,
            filter={
                'user_id': user_id,
                'importance': 'high',
                'is_active': True
            },
            limit=remaining_slots,
            min_score=0.8
        )
        results.extend(high_relevant)
        remaining_slots -= len(high_relevant)
    
    if remaining_slots > 0:
        # Step 3: Fill with medium/low importance
        medium_low = vector_db.search(
            embedding=context_embedding,
            filter={
                'user_id': user_id,
                'importance': ['medium', 'low'],
                'is_active': True
            },
            limit=remaining_slots,
            min_score=0.75
        )
        results.extend(medium_low)
    
    # Log access for analytics
    for memory in results:
        log_memory_access(memory.id, assignment_id)
    
    return results
```

    last_accessed_at TIMESTAMP,

        'persona', 'preference', 'fact', 'context', 'instruction'

    )),
    CONSTRAINT valid_source CHECK (source IN (
        'manual', 'inferred', 'imported'
    ))
);

### Memory System Implementation Notes

#### Vector Database Integration

Use a vector database for semantic search:
- **pgvector**: PostgreSQL extension


#### Memory Retrieval Strategy

When processing a new message in an assignment:

1. **Extract context** from recent messages
2. **Query vector DB** with context embedding
3. **Filter and rank** by relevance + recency + access count
4. **Inject top N memories** into system prompt
5. **Log access** for analytics
